What is an LLM?

The core idea behind ChatGPT, Llama, Gemma and every model you'll run.

A Large Language Model (LLM) is a program trained on huge amounts of text to do one thing extremely well: predict the next token (a word or piece of a word). By predicting one token, adding it, and predicting again, it writes whole answers, code and essays.

1. Training (done by Meta, Google, etc.)
The model reads trillions of words and learns patterns. This costs millions of dollars of GPU time.
2. Weights
What it learned is stored as billions of numbers called parameters or weights. That's the file you download.
3. Inference (what Ollama does)
Loading the weights and using them to generate text. This happens on your computer.

Tokens: how models read text

Models don't see letters or whole words. They see tokens, chunks of about 3–4 characters on average. In English, 100 tokens ≈ 75 words. Limits, speed (“tokens per second”) and context size are all measured in tokens.

Key concepts you must know

Parameters, quantization, context window, temperature, CPU vs GPU, local vs cloud.

Parameters & quantization: why model size matters

Parameters are the model's learned numbers. More parameters usually means a smarter model but a bigger file and slower answers. Sizes are written as 1b (1 billion), 270m (270 million), 70b, and so on.

Quantization compresses each number. Full precision (fp16) uses 16 bits per parameter; q8_0 uses about 8 bits; q4_K_M (Ollama's usual default) uses about 4.5 bits. That's about ¼ of the size with only a small loss in quality.

Context window: the model's short-term memory

The context window (num_ctx) is how many tokens the model can “see” at once: your messages, its replies and any documents. When a chat gets longer than the window, the oldest tokens fall out and the model forgets them. Bigger windows remember more but use more RAM.

Temperature & sampling: creative or focused?

After scoring each possible next token, the model samples one. Temperature reshapes the odds: low (0–0.3) almost always picks the top token, which is predictable and good for facts and code. High (0.8–1.5) gives rare tokens a chance, which is creative but can go off topic. Related settings are top_k (consider only the K best tokens), top_p (consider the smallest set adding up to P probability), repeat_penalty and seed (same seed + same settings = same answer).

CPU vs GPU

🧠 CPU + RAM
Works on every computer. Fine for 1B–4B models. Expect roughly 5–20 tokens/second.
⚡ GPU + VRAM
NVIDIA (CUDA), AMD (ROCm) or Apple Silicon (Metal). Often 3–10× faster. The model must fit in VRAM to be fully fast.
🔀 Split
If a model is bigger than VRAM, Ollama puts part on the GPU and the rest on the CPU. That works, but it's slower. ollama ps shows the split.

Local vs cloud AI

☁️ Cloud AI (ChatGPT, Claude, Gemini) ✔ Most powerful models · ✔ No hardware needed
✘ Needs internet · ✘ Costs money / limits · ✘ Data leaves your PC
💻 Local AI (Ollama) ✔ Free · ✔ Private · ✔ Offline · ✔ Great for learning
✘ Limited by your hardware · ✘ Smaller models are less capable

What is Ollama and how does it work?

The pieces inside, and what happens when you press Enter.

Ollama is a free, open-source tool (MIT license) that makes running LLMs as easy as ollama run llama3.2. It downloads models, manages them, runs them on your CPU/GPU, and offers an API so your own apps can use them.

CLI
The ollama command. It's just a client that sends requests to the server.
Server
Runs in the background (the tray app on Windows/macOS, a systemd service on Linux). Listens on port 11434.
Registry
ollama.com/library, where pull downloads models from (like Docker Hub, for AI).
GGUF
The file format for the weights. You can also import .gguf files from Hugging Face.
Modelfile
A recipe (like a Dockerfile) for building custom models with your own system prompt and settings.
Load / unload
A model is loaded into memory on first use and unloaded after 5 idle minutes (keep_alive).
AnalogyOllama is to AI models what Docker is to apps: pull an image (model), run it, list / rm / cp it, and build your own from a recipe file.

0 of 6 steps done
  • Download the installer
    Open ollama.com/download/windows → Download for Windows. You get OllamaSetup.exe (~1 GB) in Downloads.
  • Run OllamaSetup.exe
    Double-click → Install. No admin rights needed: it installs to %LOCALAPPDATA%\Programs\Ollama. If SmartScreen warns, click More info → Run anyway (only for the file from ollama.com).
    Optional: install to another folder
    .\OllamaSetup.exe /DIR="D:\Ollama"
  • Look for the 🦙 tray icon
    After install, Ollama starts automatically and a llama icon appears near the clock. That means the server is running.
  • Open a NEW terminal
    Start → type PowerShell (or cmd / Windows Terminal). It must be new so it picks up the updated PATH.
  • Check the version
    ollama --version
ollama version is 0.x.x
  • Run your first model
    ollama run llama3.2:1b
“ollama is not recognized…”Close every terminal (including VS Code's) and open a new one. Still failing? Sign out of Windows and back in.

basics.py
import ollama

# 1. single prompt
r = ollama.generate(model="llama3.2", prompt="Why is the sky blue? One line.")
print(r["response"])

# 2. chat with roles
r = ollama.chat(model="llama3.2", messages=[
    {"role": "system", "content": "You are a helpful tutor."},
    {"role": "user", "content": "Explain Python dictionaries in 3 lines."},
])
print(r["message"]["content"])

# 3. streaming
for chunk in ollama.chat(model="llama3.2", stream=True,
                         messages=[{"role": "user", "content": "Tell me a short joke"}]):
    print(chunk["message"]["content"], end="", flush=True)

# 4. options (same as PARAMETER / /set parameter)
r = ollama.chat(model="llama3.2",
                messages=[{"role": "user", "content": "Name 3 colors"}],
                options={"temperature": 0.2, "num_ctx": 8192, "seed": 42},
                keep_alive="10m")

# 5. manage models from code
ollama.pull("gemma3:1b")
print([m["model"] for m in ollama.list()["models"]])

    
chatbot.py: remembers the conversation
import ollama

history = [{"role": "system", "content": "You are a friendly study buddy."}]
while True:
    user = input("You: ")
    if user.lower() in ("exit", "quit"):
        break
    history.append({"role": "user", "content": user})
    reply = ""
    print("Bot: ", end="")
    for chunk in ollama.chat(model="llama3.2", messages=history, stream=True):
        piece = chunk["message"]["content"]
        reply += piece
        print(piece, end="", flush=True)
    print()
    history.append({"role": "assistant", "content": reply})

Embeddings & RAG (chat with your own documents)

  
An embedding turns text into a list of numbers (a vector) so that texts with similar meanings have similar vectors. RAG (Retrieval-Augmented Generation) uses this to find the relevant parts of your documents and hand them to the LLM, so it can answer about things it was never trained on.

  

    
🧪 Lab: animated RAG pipeline

    

    
Press play to watch a question flow through a RAG app.

    

  

  
mini_rag.py (no extra libraries)
import ollama, math
# ollama pull nomic-embed-text   and   ollama pull llama3.2

docs = [
    "Ollama runs large language models locally on port 11434.",
    "The ollama ps command shows models loaded in memory.",
    "Use ollama rm to delete a model and free disk space.",
]

def embed(texts):
    return ollama.embed(model="nomic-embed-text", input=texts)["embeddings"]

def cosine(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    return dot / (math.sqrt(sum(x * x for x in a)) * math.sqrt(sum(y * y for y in b)))

doc_vecs = embed(docs)                                   # 1. index documents
question = "How do I free up disk space?"
q_vec = embed([question])[0]                             # 2. embed the question
best = max(range(len(docs)), key=lambda i: cosine(q_vec, doc_vecs[i]))  # 3. search

answer = ollama.chat(model="llama3.2", messages=[        # 4. generate with context
    {"role": "system", "content": "Answer only using the context."},
    {"role": "user", "content": f"Context: {docs[best]}\n\nQuestion: {question}"},
])
print(answer["message"]["content"])


  
Tool (function) calling

  
Models with the tools badge can ask your code to run a function (get the weather, query a database, do maths), then use the result in their answer. This is how AI agents work.

  

    
🧪 Lab: tool-calling flow

    

    
Press play.

    

  

  
tools.py
import ollama

def add_numbers(a: int, b: int) -> int:
    """Add two numbers.

    Args:
      a: first number
      b: second number
    """
    return a + b

messages = [{"role": "user", "content": "What is 1234 + 5678?"}]
r = ollama.chat(model="llama3.2", messages=messages, tools=[add_numbers])  # pass the function

if r.message.tool_calls:
    messages.append(r.message)
    for call in r.message.tool_calls:
        result = add_numbers(**call.function.arguments)              # YOUR code runs it
        messages.append({"role": "tool", "content": str(result), "tool_name": call.function.name})
    final = ollama.chat(model="llama3.2", messages=messages)
    print(final.message.content)   # "1234 + 5678 = 6912"

Troubleshooting
The errors students hit most, and the fixes.

  
“ollama is not recognized as an internal or external command”
Open a NEW terminal (close VS Code too). Check that %LOCALAPPDATA%\Programs\Ollama\ollama.exe exists. For the zip install, check your PATH. Sign out and back in.

  
“Error: could not connect to ollama app, is it running?”
The server isn't running. Open Ollama from the Start menu (look for the tray icon) or run ollama serve in another terminal.

  
“listen tcp 127.0.0.1:11434: bind: Only one usage of each socket address…”
It's already running, which is fine. Skip serve. To see what's on the port: netstat -ano | findstr 11434.

  
“Error: pull model manifest: file does not exist”
The model name or tag is wrong. Check spelling on ollama.com/library (e.g. llama3.2, not llama-3.2).

  
“model requires more system memory than is available”
Pick a smaller tag (:1b, :3b), close apps, or reduce num_ctx.

  
“does not support generate” / “does not support chat”
It's an embedding model. Use /api/embed or ollama.embed() instead of run/chat.

  
Very slow replies or laptop freezes
Use a 1B–3B model, check ollama ps for GPU vs CPU, update GPU drivers, and ollama stop models you're not using.

  
GPU not used (100% CPU)
Update NVIDIA/AMD drivers and restart Ollama. Check nvidia-smi works. Check server.log for “no compatible GPUs”. Very old GPUs aren't supported.

  
Download stuck / slow / fails on college Wi-Fi
Ctrl+C and re-run pull (it resumes). Behind a proxy, set HTTPS_PROXY and restart Ollama. Try a mobile hotspot if the network blocks it.

  
C: drive full
ollama list → ollama rm unused models, or move them with OLLAMA_MODELS.

  
Answers are wrong or made up (hallucinations)
Small models make mistakes. Try a bigger model, lower the temperature, give context (RAG), and always verify facts.

  
Browser app gets a CORS error
Set OLLAMA_ORIGINS to your app's origin (or * for local testing) and restart Ollama.

  
Where are the logs?
Windows: explorer %LOCALAPPDATA%\Ollama → server.log. macOS: ~/.ollama/logs/server.log. Linux: journalctl -u ollama.
