Run AI models on your own computer with Ollama

A step-by-step guide: download and install Ollama, learn every ollama command, and run free open models like Llama, Gemma, Qwen, Phi and DeepSeek offline on your laptop.

1. What is Ollama?

Ollama is a free, open-source tool that downloads large language models (LLMs) and runs them locally on your machine. No API key, no internet once the model is downloaded, and your data never leaves your computer.

You type ollama run llama3.2→ Ollama CLI→ Ollama server
localhost:11434→ Model file on disk
loaded into RAM / GPU→ Answer streams back
🔒 Private
Prompts and documents stay on your laptop.
💸 Free
No per-token billing. The models are open-weight.
✈️ Offline
After pull, works with Wi-Fi off.
🧩 Developer-friendly
REST API on port 11434, plus Python and JS libraries.
Two parts to know The server runs in the background and does the work. The CLI (ollama ... commands) talks to that server. On Windows and macOS, the desktop app starts the server for you automatically.

Check your RAM on Windows: press Ctrl + Shift + Esc → Performance → Memory. Or in PowerShell:

3. Installation

Pick your operating system:

Windows: download and run the installer

  1. Open the download page
    Go to https://ollama.com/download and choose Windows. Click Download for Windows.
  2. Find the file
    The file OllamaSetup.exe (around 1 GB) lands in your Downloads folder.
  3. Run the installer
    Double-click OllamaSetup.exe → click Install. It installs only for your user, so admin rights are not needed. Default location:
    C:\Users\<you>\AppData\Local\Programs\Ollama
  4. Look for the llama icon
    When it finishes, Ollama starts and a 🦙 icon appears in the system tray (bottom-right, near the clock). That means the server is running.
  5. Open a NEW terminal
    Press Win, type PowerShell or cmd, and open it. Open a fresh window so it picks up the new PATH.
  6. Check it works
    PowerShell / cmd
    ollama --version
ollama version is 0.x.x
“ollama is not recognized…”?Close all terminal windows (including the one inside VS Code) and open a new one. If it still fails, sign out of Windows and back in. Also see Troubleshooting.
Windows also has a desktop chat appThe newer Ollama for Windows includes a simple chat window (open it from the Start menu). This guide focuses on the terminal commands because they work the same on every OS.

Windows: manual (portable) install without the installer

Use this if your lab PC blocks installers, or you want Ollama on another drive such as D:.

  1. Download the zip
    Open github.com/ollama/ollama/releases/latest and download ollama-windows-amd64.zip (use ollama-windows-arm64.zip on ARM laptops such as Snapdragon).
  2. Extract it
    Right-click → Extract All… → for example D:\tools\ollama. You should see ollama.exe in that folder.
  3. Add the folder to PATH
    Press Win → search “Edit environment variables for your account” → select Path → Edit → New → paste D:\tools\ollama → OK. Or use PowerShell:
    PowerShell
    [Environment]::SetEnvironmentVariable("Path", $env:Path + ";D:\tools\ollama", "User")
  4. (Optional) Keep models on D: too
    PowerShell
    [Environment]::SetEnvironmentVariable("OLLAMA_MODELS", "D:\ollama-models", "User")
  5. Start the server yourself
    The zip has no tray app, so open a new terminal and keep it running:
    Terminal 1: leave open
    ollama serve
... Listening on 127.0.0.1:11434
  6. Use Ollama in a second terminal
    Terminal 2
    ollama --version
ollama run llama3.2:1b

macOS

  1. Go to ollama.com/download → macOS → download Ollama.dmg.
  2. Open the .dmg and drag Ollama into Applications.
  3. Open Ollama from Applications. Allow it to install the command-line tool when asked. A 🦙 icon appears in the menu bar.
  4. Open Terminal and run ollama --version.
Alternative: Homebrew
brew install ollama
ollama serve   # run in its own Terminal tab

Linux

One command installs Ollama and sets it up as a background service (systemd):

bash
curl -fsSL https://ollama.com/install.sh | sh

Check and manage the service:

bash
ollama --version
systemctl status ollama      # is it running?
sudo systemctl restart ollama # restart after changing settings
journalctl -u ollama -f       # live logs

4. Verify the install

Run these three checks. If all pass, you are ready.

Terminal
# 1. CLI is on PATH
ollama --version

# 2. Server is running (should print "Ollama is running")
curl http://localhost:11434

# 3. List models (empty the first time; that's fine)

You can also open http://localhost:11434 in your browser. It should say “Ollama is running”.

PowerShell noteIn Windows PowerShell, curl is an alias for Invoke-WebRequest. Use curl.exe http://localhost:11434 to call the real curl.

  run         Run a model
  stop        Stop a running model
  pull        Pull a model from a registry
  push        Push a model to a registry

  signout     Sign out from ollama.com

ollama serve server

Starts the Ollama server (the engine) on http://127.0.0.1:11434.

When do I need it? Only if the server is not already running: the manual zip install, Linux without systemd, or Docker. On Windows and macOS the tray/menu-bar app runs it for you.

ollama serve                       # start (keep this window open)

# Windows PowerShell: make it reachable from other devices on your network
$env:OLLAMA_HOST="0.0.0.0:11434"; ollama serve

# Linux / macOS
OLLAMA_HOST=0.0.0.0:11434 ollama serve
Error: “bind: Only one usage of each socket address…”The server is already running (usually the tray app). You don't need serve, so use the other commands. To run it yourself, first quit Ollama from the tray icon.

ollama run <model> most used

Runs a model and opens an interactive chat. It downloads the model first if you don't have it.

# interactive chat
ollama run llama3.2

# a specific size or version (tag)
ollama run qwen3:1.7b

# one-shot: ask a question, print the answer, exit
ollama run llama3.2 "Write a Python function to reverse a string"

# show speed stats (tokens/sec) after each answer
ollama run llama3.2 --verbose

# feed a file into the prompt (PowerShell)
Get-Content notes.txt | ollama run llama3.2 "Summarize this:"
# (bash / cmd)
ollama run llama3.2 "Summarize this:" < notes.txt

# image input with a vision model
ollama run gemma3:4b "What is in this picture? ./photo.jpg"

# reasoning models: hide or show the thinking
ollama run deepseek-r1:1.5b --think=false

# keep the model in memory for 30 minutes after exit
ollama run llama3.2 --keepalive 30m

# ask for JSON output
ollama run llama3.2 --format json "List 3 fruits with colors as JSON"

Model names follow name:tag. With no tag, Ollama uses :latest (the default size). Example: llama3.2 = llama3.2:latest = the 3B version.

ollama pull <model> download

Downloads a model from the Ollama library without starting a chat. Running it again on a model you have updates it.

ollama pull llama3.2
ollama pull gemma3:1b
ollama pull nomic-embed-text      # embedding model, for RAG projects

Browse every available model at ollama.com/library. Downloads resume if your internet drops: just run the same command again.

ollama list alias: ls

Shows every model downloaded on your machine, with size and when it was last changed.

ollama list
NAME               ID              SIZE      MODIFIED
llama3.2:latest    a80c4f17acd5    2.0 GB    2 hours ago
gemma3:1b          8648f39daa8f    815 MB    3 days ago
mistral:latest     f974a74358d6    4.1 GB    1 week ago

ollama ps monitor

Lists models that are loaded in memory right now, and whether they use the GPU or CPU.

ollama ps
NAME               ID              SIZE      PROCESSOR    CONTEXT    UNTIL
llama3.2:latest    a80c4f17acd5    3.1 GB    100% GPU     4096       4 minutes from now

PROCESSOR tells you where it runs: 100% GPU is fast; 100% CPU is slower; a split like 48%/52% CPU/GPU means the model didn't fit in GPU memory. UNTIL is when it will be unloaded automatically (5 minutes idle by default).

ollama stop <model> free memory

Unloads a running model from RAM/GPU straight away. The model stays on disk.

ollama ps              # see what's loaded
ollama stop llama3.2   # unload it

Handy before switching to a big model, or when your laptop feels slow.

ollama show <model> inspect

Shows details about a model: architecture, parameter count, context length, quantization, capabilities and license.

ollama show llama3.2
  Model
    architecture        llama
    parameters          3.2B
    context length      131072
    embedding length    3072
    quantization        Q4_K_M
  Capabilities
    completion
    tools

ollama show llama3.2 --modelfile    # the Modelfile it was built from
ollama show llama3.2 --parameters   # default settings (temperature, stop words)
ollama show llama3.2 --template     # the prompt template
ollama show llama3.2 --system       # the system prompt, if any
ollama show llama3.2 --license     # license text

Tip: --modelfile output is a good starting point for your own custom model.

ollama create <name> -f Modelfile customize

Builds a new model from a Modelfile, a small text recipe that sets a base model, a system prompt and parameters.

ollama create python-tutor -f Modelfile
gathering model components
using existing layer sha256:...
writing manifest
success
ollama run python-tutor

Full walkthrough in section 9. You can also import a downloaded .gguf file with FROM ./model.gguf.

ollama cp <source> <destination> copy

Copies (or renames) a model under a new name. It's instant and uses almost no disk space, because the data is shared.

ollama cp llama3.2 my-llama
ollama cp python-tutor yourusername/python-tutor   # rename before push

ollama rm <model> delete

Deletes a model from disk to free space.

ollama rm mistral
deleted 'mistral'
ollama rm gemma3:1b qwen3:1.7b   # several at once
CarefulThere is no recycle bin. You'd need to pull the model again (re-download) to get it back.

ollama signin / ollama signout account

Connects your terminal to your free account on ollama.com, or disconnects it.

ollama signin     # prints a link; open it in your browser and approve
ollama signout

Do I need an account? No for running local models. You only need to sign in to push your own models, or to use Ollama's optional cloud models (names ending in -cloud), which run on Ollama's servers instead of your laptop.

ollama push <username/model> share

Uploads your custom model to ollama.com so classmates can pull it.

ollama signin
ollama cp python-tutor yourusername/python-tutor   # name must start with your username
ollama push yourusername/python-tutor

# a classmate can now run:
ollama run yourusername/python-tutor

ollama launch integrations

Opens the Ollama menu, or starts a supported tool (for example a coding assistant) already set up to use your local Ollama models.

ollama launch                 # interactive menu: pick an integration
ollama launch --help          # see which integrations your version supports
ollama launch <integration>   # start one directly

This is a newer command and the list of integrations changes between versions, so check ollama launch --help on your machine. If your version doesn't have it, update Ollama.

ollama help & flags help

Shows help for Ollama or for one command.

ollama help             # all commands
ollama help run         # all flags for "run"
ollama run --help       # same thing
ollama -v               # version (same as --version)

No command matches that filter.

How do I find ALL the free models available?

The table above is only a starting point. The Ollama Library lists 200+ free models, with new ones added every week. Here's how to explore it.

  1. Open the official library
    https://ollama.com/library shows every official model. Use Sort by → Popular to see what most people use, or Newest to see the latest releases.
  2. Search by name or task
    Use the search box at ollama.com/search. Try words like coder, vision, embed, math, ocr.
  3. Filter by capability
    These links show only models with that skill: tools · vision · thinking · embedding · cloud
  4. Open the model page and pick a size
    Click a model, open the Tags tab, and pick a size that fits your RAM (see reading a model page). Copy the command shown, e.g. ollama run gemma3:1b.
  5. Check what you already have 
    ollama list              # models on YOUR computer
ollama show gemma3:1b    # details + capabilities of one model
There is no “ollama search” commandThe CLI can only list models you've already downloaded (ollama list). To browse what's available, use the website.

Reading a model page: tags, sizes, quantization

Every model has several tags (versions). The tag is the part after the colon:

Anatomy of a model name
  gemma3 : 4b - it - q4_K_M
  └─┬──┘   └┬┘   └┬┘  └──┬──┘
  model   size  type  quantization (compression)
PartWhat it meansHow to choose
Size
270m, 1b, 4b, 8b, 70b		Number of parameters (m = million, b = billion). Bigger = smarter but slower and needs more RAM.8 GB RAM → ≤ 3–4b · 16 GB → ≤ 8b · 32 GB → ≤ 14b
e2b / e4b“Effective” size: models built for phones and laptops (Gemma 3n, Gemma 4)Great for low-end hardware
8x7b, 16x17bMixture of Experts (MoE): many expert blocks, only some used per wordTotal size is still large, so check the GB number
Quantization
q4_K_M, q8_0, fp16		How compressed the weights are. q4 is about ¼ the size of fp16 with small quality loss.Use the default (q4_K_M). Use q8_0 only if you have spare RAM.
instruct / it / chatTuned to follow instructions and chatPick this for normal use
text / baseRaw model that only continues textUsually not what students want
latestThe default tag used when you leave it outollama run gemma3 = gemma3:latest
Quick size estimateAt the default 4-bit quantization, the download is roughly 0.6 × billions of parameters GB. So a 7B model is about 4–5 GB, a 3B model about 2 GB, and a 1B model about 0.8 GB. The exact size is listed next to each tag on the model's Tags page.

9. Build your own custom model (Modelfile)

A Modelfile is like a recipe: start from a base model, then add your own personality and settings.

  1. Make a folder and a file named Modelfile (no extension):
    Modelfile
    # base model (must be pulled, or Ollama pulls it)
FROM llama3.2

# settings
PARAMETER temperature 0.4
PARAMETER num_ctx 4096

# personality
SYSTEM """
You are PyBuddy, a patient Python tutor for college students.
Always explain with a short example, then ask one practice question.
Keep answers under 150 words.
"""
  2. Build it 
    ollama create pybuddy -f Modelfile
  3. Run it 
    ollama run pybuddy "What is a list comprehension?"
  4. Check, copy, remove 
    ollama list                 # pybuddy appears here
ollama show pybuddy --modelfile
ollama rm pybuddy
InstructionMeaning
FROMBase model name, or a path to a .gguf file (FROM ./my-model.gguf)
SYSTEMThe system prompt: role, rules, tone
PARAMETERtemperature, num_ctx, top_p, top_k, repeat_penalty, stop, seed
TEMPLATEThe prompt format (advanced: usually keep the base model's)
MESSAGEExample conversation turns: MESSAGE user Hi / MESSAGE assistant Hello!
ADAPTERApply a LoRA fine-tune adapter
LICENSELicense text for your model

10. Use Ollama from your code (REST API)

While Ollama runs, it serves an HTTP API at http://localhost:11434. Any language can call it.

Official Python library

Terminal
pip install ollama
chat.py
import ollama

response = ollama.chat(
    model="llama3.2",
    messages=[
        {"role": "system", "content": "You are a helpful tutor."},
        {"role": "user", "content": "Explain Python dictionaries in 3 lines."},
    ],
)
print(response["message"]["content"])

# Streaming: print words as they arrive
for chunk in ollama.chat(model="llama3.2",
                         messages=[{"role": "user", "content": "Tell me a short joke"}],
                         stream=True):
    print(chunk["message"]["content"], end="", flush=True)
Simple chatbot with memory
import ollama

history = []
while True:
    user = input("You: ")
    if user.lower() in ("exit", "quit"):
        break
    history.append({"role": "user", "content": user})
    reply = ollama.chat(model="llama3.2", messages=history)["message"]["content"]
    history.append({"role": "assistant", "content": reply})
    print("Bot:", reply)

Reuse OpenAI code: just change the URL

Ollama provides an OpenAI-compatible endpoint at /v1, so code written for ChatGPT can run on a local model.

Terminal
pip install openai
openai_local.py
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")  # key is ignored

resp = client.chat.completions.create(
    model="llama3.2",
    messages=[{"role": "user", "content": "Give me 3 project ideas using Flask."}],
)
print(resp.choices[0].message.content)

curl (Git Bash, macOS, Linux)

# one-shot generate
curl http://localhost:11434/api/generate -d '{
  "model": "llama3.2",
  "prompt": "Why is the sky blue?",
  "stream": false

# chat with messages
curl http://localhost:11434/api/chat -d '{
  "model": "llama3.2",
  "messages": [{"role": "user", "content": "Hello!"}],
  "stream": false

Move models to the D: drive (Windows)

  1. Quit Ollama: right-click the 🦙 tray icon → Quit Ollama.
  2. Set the variable:

  4. Start Ollama again from the Start menu, and open a new terminal. Run ollama list to confirm.

12. Troubleshooting

“ollama is not recognized as an internal or external command”

The terminal doesn't know where ollama.exe is.

  • Close every terminal and VS Code, then open a new one.
  • Check the file exists: dir $env:LOCALAPPDATA\Programs\Ollama
  • For the zip install, make sure the folder is in your user Path (see the manual install tab).
  • Still stuck? Sign out of Windows and back in, or reinstall.
“Error: could not connect to ollama app, is it running?”

The server isn't running. Start the Ollama app from the Start menu (look for the tray icon), or run ollama serve in a separate terminal.

“listen tcp 127.0.0.1:11434: bind: Only one usage of each socket address…”

The server is already running, which is fine. Skip ollama serve and use ollama run directly. To see what is using the port:

netstat -ano | findstr 11434
Replies are extremely slow / laptop freezes
  • Use a smaller model: llama3.2:1b, gemma3:1b, qwen3:0.6b.
  • Close Chrome tabs and other heavy apps to free RAM.
  • Run ollama ps. If it says 100% CPU on a GPU laptop, update your NVIDIA/AMD drivers.
  • Unload models you're not using: ollama stop <model>.
“model requires more system memory than is available”

The model is too big for your RAM. Choose a smaller tag (for example :1b or :3b), or close other programs.

Download stuck or failed

Press Ctrl + C and run the same ollama pull again. It resumes where it stopped. On college Wi-Fi with a proxy, set HTTPS_PROXY before starting Ollama.

C: drive is full

Run ollama list and ollama rm the models you don't need, or move models to another drive with OLLAMA_MODELS (section 11).

How do I update or uninstall Ollama?
  • Update (Windows/macOS): the app updates itself. Click the tray icon → Restart to update when it offers. Or download and run the newest installer over the old one.
  • Update (Linux): run the install script again.
  • Uninstall (Windows): Settings → Apps → Installed apps → Ollama → Uninstall. Then delete C:\Users\<you>\.ollama to remove downloaded models.

# ---------- setup ----------
ollama --version                     # check install
ollama serve                         # start server (if not running)

# ---------- models ----------
ollama pull llama3.2                 # download

ollama show llama3.2                 # details

ollama rm my-llama                   # delete

ollama run llama3.2                  # chat
ollama run llama3.2 "question"       # one-shot answer
ollama run llama3.2 --verbose        # show speed
ollama ps                            # loaded models (GPU/CPU)
ollama stop llama3.2                 # unload from memory

ollama signin                        # log in to ollama.com
ollama push user/pybuddy             # share it
ollama signout

# ---------- other ----------
ollama launch                        # integrations menu

14. Practice tasks for students

Task 1: Install & verify
Install Ollama, then take a screenshot of ollama --version and ollama list.
Task 2: First chat
Run llama3.2:1b, ask 3 questions from your syllabus, exit with /bye.
Task 3: Compare models
Ask two models the same question with --verbose. Record tokens/sec and which answer was better.
Task 4: Monitor
While a model is chatting, open a second terminal and run ollama ps. Is it on GPU or CPU? Then ollama stop it.
Task 5: Custom model
Write a Modelfile for a “Resume Reviewer” or “SQL Tutor”, create it, and test it.
Task 6: Code it
Write a Python chatbot with the ollama library that remembers history. Bonus: wrap it in a Flask or FastAPI route.
Task 7: Clean up
Use ollama cp to make a copy, then ollama rm both the copy and one unused model. Check free space.
