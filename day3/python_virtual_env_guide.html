Python Virtual Environments

What they are, why every Python learner needs them, and how to create one step by step

1. What is a Virtual Environment?

A virtual environment (venv) is an isolated folder that contains its own Python interpreter and its own set of installed libraries (packages).

Think of it as a separate toolbox for each project. Whatever you install inside one toolbox does not leak into the others.

Project A
pandas 1.5 Project B
pandas 2.2 Project C
Django 5

Each project has its own environment, so versions never clash.

2. Why Do We Need It?

Version conflicts

Project A needs numpy 1.26 while Project B needs numpy 2.0. Only one can be installed globally at a time. A venv solves this.

Clean system Python

Installing random libraries globally can break Python itself or other tools on your computer.

Reproducibility

Export the exact list with pip freeze > requirements.txt. Anyone can rebuild the same setup on their machine.

Team and deployment

Colleagues and servers get the same libraries, which removes "it works on my machine" problems.

Easy cleanup

Delete the folder and the environment is gone. Nothing else on your system is affected.

3. Procedure to Create a Virtual Environment

Windows macOS / Linux Commands are shown for each. Open a terminal inside your project folder first.

1

Check that Python is installed

Windows

python --version

macOS / Linux

python3 --version
2

Go to your project folder

cd D:\getwork\day3
3

Create the environment

The name venv is the usual convention. The command creates a folder called venv.

Windows

python -m venv venv

macOS / Linux

python3 -m venv venv
4

Activate the environment

Windows (PowerShell)

.\venv\Scripts\Activate.ps1

Windows (Command Prompt)

venv\Scripts\activate.bat

macOS / Linux

source venv/bin/activate

When it works, the prompt starts with (venv):

(venv) PS D:\getwork\day3>
5

Install packages inside it

pip install pandas numpy

Packages go only into venv, not into the system Python.

6

Save your dependencies (optional, recommended)

pip freeze > requirements.txt

Later, or on another machine, restore everything with:

pip install -r requirements.txt
7

Deactivate when finished

deactivate

4. Common Problems and Fixes

"running scripts is disabled on this system" (PowerShell)
Allow local scripts for your user account only, then try activating again: 
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
"python is not recognized"
Python is not on your PATH. Reinstall Python from python.org and tick "Add python.exe to PATH", or use the py launcher: py -m venv venv.
Delete and recreate a broken environment
The environment is just a folder, so it is safe to delete and rebuild: 
deactivate
Remove-Item -Recurse -Force venv
python -m venv venv

5. Important: Do Not Commit the venv

The venv folder is large and specific to your machine. Add it to .gitignore: 

venv/
__pycache__/
*.pyc

Commit requirements.txt instead, so others can recreate the environment.
