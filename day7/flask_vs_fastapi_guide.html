Day 7 · Python web backends

FlaskvsFastAPI

Both are Python tools for building the backend of an app: the part that receives a request, does some work, and sends back an answer. On Day 6 you built a task app with Flask. Today you will see the same app in FastAPI and learn what changed, why it matters, and when to pick each one.

"A micro framework. Start tiny, add what you need."

Born

Built on
Werkzeug (web tools) + Jinja2 (HTML templates)
Standard

Style
Sync first. You write the checks and docs yourself.
Great for

FastAPI

"Write normal Python type hints. Get checks, docs and speed for free."

Born
2018, by Sebastián Ramírez
Built on
Starlette (web tools) + Pydantic (data checks)
Standard
ASGI — one worker can juggle many requests
Style
Async ready. Validation and docs are automatic.
Great for
JSON APIs, AI / LLM backends, microservices
Lesson 1 · Sync vs async

The waiter story: who wastes time waiting?

Most of a backend's time is spent waiting: for the database, for another website, or for an AI model like ChatGPT or Claude to answer. What a framework does while it waits is the biggest difference between Flask and FastAPI.

Flask waiter (sync)

Takes the order from table 1, gives it to the kitchen, and stands at the kitchen door until the food is ready. Only then does table 2 get a menu.

FastAPI waiter (async)

Takes the order from table 1, gives it to the kitchen, and goes straight to table 2, then table 3. When a dish is ready, the waiter serves it.

Flask · 1 sync worker

0.0s

FastAPI · 1 async worker

0.0s
Waiting in line Python code running (0.1s) Waiting for database / AI model

Fair play: real Flask apps run several workers or threads (for example gunicorn -w 4), so they are not this slow. But each worker can only stand at one kitchen door at a time. Async lets one worker handle hundreds of waits, which saves memory and money. It helps most when your app waits a lot, like calling an LLM API that takes 3–10 seconds.

# Flask: the worker is blocked while it waits
@app.get("/ask")
def ask():
    answer = call_llm()      # waits 3s, worker frozen
    return {"answer": answer}
# FastAPI: "await" = go serve other tables
@app.get("/ask")
async def ask():
    answer = await call_llm()  # waits 3s, worker free
    return {"answer": answer}

Notice: FastAPI lists every mistake at once and says exactly where (loc). It also converts safe values for you: "4" becomes 4. Status 422 means "I understood your JSON, but the data is wrong".

      Lesson 5 · Type hints do the work
      
One small : int does three jobs

      
In FastAPI, writing task_id: int checks the value, converts the text "42" into the number 42, and documents it. Your code editor also starts auto-completing, because it knows the types. Try a URL:

    

    

      

        GET /tasks/

Flask has URL converters too (<int:id>), but a wrong value just gives a general 404 page. FastAPI explains the mistake. Type hints also work for query strings: def search(q: str, limit: int = 10) makes ?q=python&limit=5 work with no extra code.

  







  

    

      Lesson 6 · Dependency injection
      
Depends(): plug in shared helpers like LEGO

      
Many routes need the same things: a database connection, the logged-in user, an API key check. FastAPI lets a route ask for them, and it plugs them in before your function runs. Flask usually uses the global g object, decorators or extensions like Flask-Login for this.

    

    

      

        
get_db()opens a database session, closes it after

        
get_current_user()reads the token, returns the user or 401

        
rate_limit()blocks spammers before your code runs

        
      

      

        
@app.get("/my-tasks")
def my_tasks(
    db = Depends(get_db),
    user = Depends(get_current_user),
    _ = Depends(rate_limit),
):
    return db.tasks_for(user.id)

        
Write a helper once, reuse it in 50 routes. In tests you can swap the real database for a fake one with app.dependency_overrides.

      

    

  







  

    

      Lesson 7 · Same app, two ways
      
The full Task API, side by side

      
Both files are in this folder and do the same four things: list, create, get and delete tasks. Run them and compare.

    

    

      

        
flask_app/app.pypython app.py → :5000

        
from flask import Flask, jsonify, request

app = Flask(__name__)

tasks = []      # our "database" (a plain Python list in memory)
next_id = 1


@app.get("/tasks")
def list_tasks():
    return jsonify(tasks)


@app.post("/tasks")
def create_task():
    global next_id
    data = request.get_json(silent=True) or {}

    # Flask does NOT check the input for you.
    # Every rule below is written by hand.
    title = data.get("title")
    if not isinstance(title, str) or not title.strip():
        return jsonify({"error": "title is required"}), 400
    if len(title.strip()) > 200:
        return jsonify({"error": "title must be 200 characters or less"}), 400

    priority = data.get("priority", 3)
    # bool is a subclass of int in Python, so True would sneak through without this
    if isinstance(priority, bool) or not isinstance(priority, int):
        return jsonify({"error": "priority must be a whole number"}), 400
    if not 1 <= priority <= 5:
        return jsonify({"error": "priority must be from 1 to 5"}), 400

    task = {"id": next_id, "title": title.strip(), "priority": priority, "done": False}
    tasks.append(task)
    next_id += 1
    return jsonify(task), 201


@app.get("/tasks/<int:task_id>")
def get_task(task_id):
    for task in tasks:
        if task["id"] == task_id:
            return jsonify(task)
    return jsonify({"error": "task not found"}), 404


@app.delete("/tasks/<int:task_id>")
def delete_task(task_id):
    for task in tasks:
        if task["id"] == task_id:
            tasks.remove(task)
            return "", 204
    return jsonify({"error": "task not found"}), 404


if __name__ == "__main__":
    app.run(debug=True, port=5000)

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, ConfigDict, Field

app = FastAPI(title="Task API", version="1.0")


# The rules live in the type hints. FastAPI + Pydantic check them for you.
class TaskIn(BaseModel):
    model_config = ConfigDict(str_strip_whitespace=True)

    title: str = Field(min_length=1, max_length=200)
    priority: int = Field(default=3, ge=1, le=5)


class Task(TaskIn):
    id: int
    done: bool = False


tasks: list[Task] = []   # our "database" (a plain Python list in memory)
next_id = 1


@app.get("/tasks")
def list_tasks() -> list[Task]:
    return tasks


@app.post("/tasks", status_code=201)
def create_task(task_in: TaskIn) -> Task:
    global next_id
    task = Task(id=next_id, **task_in.model_dump())
    tasks.append(task)
    next_id += 1
    return task


@app.get("/tasks/{task_id}")
def get_task(task_id: int) -> Task:
    for task in tasks:
        if task.id == task_id:
            return task
    raise HTTPException(status_code=404, detail="task not found")


@app.delete("/tasks/{task_id}", status_code=204)
def delete_task(task_id: int) -> None:
    for task in tasks:
        if task.id == task_id:
            tasks.remove(task)
            return
    raise HTTPException(status_code=404, detail="task not found")

      

    

    

      Spot the differences: Flask uses <int:task_id> and jsonify(); FastAPI uses {task_id}, type hints and plain return values.
      FastAPI extra, for free: /docs, /redoc, /openapi.json, clear 422 errors.

      Lesson 9 · Why it mattered
      
What FastAPI changed in app development

      
FastAPI did not invent async, type hints or OpenAPI. It joined them so tightly that a normal Python function became a validated, documented, fast API. That changed how teams work.

    

    

      
Contract
Type hints became the API contract
Before: rules lived in if-statements, docs lived in a Word file.
After: one Python class is the rule, the check and the documentation.

      
Docs
Docs that never go stale
Before: someone forgot to update the API docs.
After: /docs is generated from the code on every start.

      
AI apps
The default for AI and ML backends
Before: data scientists struggled to put a model online.
After: load the model, add one route, done. Async handles slow LLM calls and token streaming.

      
Teamwork
Frontend teams generate code
Before: frontend devs guessed field names.
After: tools read /openapi.json and generate a ready TypeScript client.

      
Quality
Bugs stopped at the door
Before: bad data got saved and crashed something later.
After: wrong input gets a clear 422 before your code runs.

      
Python
Async Python went mainstream
Before: high-traffic APIs often moved to Node.js or Go.
After: Python on Uvicorn handles lots of waiting connections well, so teams can stay in Python.

    

    

      
2010Flask released (it started as an April Fools' joke).

      
2016ASGI idea appears, bringing async to Python web servers.

      
2018FastAPI first released, built on Starlette + Pydantic.

      
2021Flask 2.0 adds async def views (still on WSGI).

      
2023–24Pydantic v2 (much faster core) and the fastapi dev command.

    

  







  

    

      Lesson 10 · Common mistakes
      
Myths students believe

      
Tap each one.

    

    

      
"FastAPI is always faster than Flask."
Only when the app waits a lot (I/O-bound). If your route does heavy maths for 2 seconds (CPU-bound), both frameworks are equally stuck, because the CPU is busy. Async helps with waiting, not with computing.

      
"Just add async to everything."
Inside async def you must use async libraries. A blocking call like time.sleep() or requests.get() freezes the whole event loop, so every user waits.


# ❌ freezes everyone
async def bad():
    time.sleep(3)

# ✅ use await with async tools
async def good():
    await asyncio.sleep(3)

# ✅ or plain def: FastAPI runs it in a thread pool
def also_fine():
    time.sleep(3)

      
"Flask is old, so it is dead."
No. Flask is actively maintained, used by many companies, and has a huge set of extensions (Flask-Login, Flask-SQLAlchemy, Flask-WTF, Flask-Admin). For websites that render HTML pages, it is still a great choice.

      
"Flask cannot do async at all."
Since Flask 2.0 you can write async def views. But Flask still runs on WSGI, so each request still holds a worker until it finishes. You get async syntax, not FastAPI-style concurrency. For a fully async Flask-like framework, look at Quart.

      
"FastAPI can't serve web pages."
It can, with Jinja2Templates and StaticFiles. It is just designed API-first, so Flask feels more natural for template-heavy websites.

      
"Type hints in Python are just comments."
Plain Python ignores them at runtime. FastAPI and Pydantic read them while the app runs and use them to check, convert and document data. That is FastAPI's main trick.
