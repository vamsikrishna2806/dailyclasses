The 3-Tier Architecture

Almost every app you use (Swiggy, Instagram, ChatGPT, your bank) splits into three layers. Each layer has one job, and they talk to each other in a fixed order.

Restaurant analogy

🍽️

Frontend = Dining area & menu

What the customer sees and touches: the menu, the table, the waiter taking the order. Looks matter here.

👨‍🍳

Backend = Kitchen

Hidden from customers. Takes the order, follows recipes (business rules), checks stock, and prepares the dish.

🧊

Persistence = Store room / fridge

Where ingredients are kept safely and stay there after the restaurant closes for the night.

Persistence Data Persistence Layer

"Persistence" means the data survives after the program stops or the server restarts. Different data shapes need different kinds of storage.

Relational (SQL) NoSQL AI / Specialised Files & Access layer

SQL vs NoSQL at a glance

SQL (Relational)NoSQL
Data shapeTables with fixed columnsDocuments, key-value, graph, wide-column
SchemaDefined up front (strict)Flexible, can change per record

One App Through All Three Layers

Let's follow a single click: a student presses "Enroll" on a course. Here's what each layer does, with real code: HTML + JavaScript → Flask → SQLite (via SQLAlchemy).

Watch the request travel
1 Click "Enroll"→ 2 fetch POST /api/enroll→ 3 Flask validates→ 4 INSERT into SQLite→ 5 201 + JSON→ 6 UI shows ✅
1

Frontend index.html

Shows the button and sends the data to the backend with fetch(). It does not know where the data is stored.

templates/index.html 
<!doctype html>
<html>
<body>
  <h2>GenAI Bootcamp</h2>
  <input id="name" placeholder="Your name">
  <button onclick="enroll()">Enroll</button>
  <p id="msg"></p>
  <ul id="list"></ul>

  <script>
    async function enroll() {
      const name = document.getElementById("name").value;
      const res = await fetch("/api/enroll", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ student: name, course: "GenAI Bootcamp" })
      });
      const data = await res.json();
      document.getElementById("msg").textContent =
        res.ok ? "✅ Enrolled! id = " + data.id : "❌ " + data.error;
      loadList();
    }

    async function loadList() {
      const res = await fetch("/api/enrollments");
      const rows = await res.json();
      document.getElementById("list").innerHTML =
        rows.map(r => "<li>" + r.student + " → " + r.course + "</li>").join("");
    }
    loadList();
  </script>
</body>
</html>

Backend app.py (Flask)

Receives the request, validates it (business rules), saves it through the data layer, and returns JSON with a proper status code.

app.py 
from flask import Flask, request, jsonify, render_template
from models import db, Enrollment

app = Flask(__name__)
app.config["SQLALCHEMY_DATABASE_URI"] = "sqlite:///school.db"
db.init_app(app)

with app.app_context():
    db.create_all()                      # create tables if missing

@app.get("/")
def home():
    return render_template("index.html")

@app.post("/api/enroll")
def enroll():
    data = request.get_json()
    student = (data.get("student") or "").strip()
    if not student:                      # business rule / validation
        return jsonify(error="Name is required"), 400

    row = Enrollment(student=student, course=data["course"])
    db.session.add(row)
    db.session.commit()                  # persisted!
    return jsonify(id=row.id), 201

@app.get("/api/enrollments")
def list_enrollments():
    rows = Enrollment.query.all()
    return jsonify([{"student": r.student, "course": r.course} for r in rows])

if __name__ == "__main__":
    app.run(debug=True)

Persistence models.py (SQLAlchemy + SQLite)

Defines the table. SQLAlchemy (an ORM) turns Python objects into SQL. Swapping to PostgreSQL later means changing only the connection string.

models.py 
from flask_sqlalchemy import SQLAlchemy

db = SQLAlchemy()

class Enrollment(db.Model):
    id      = db.Column(db.Integer, primary_key=True)
    student = db.Column(db.String(100), nullable=False)
    course  = db.Column(db.String(100), nullable=False)

# What SQLAlchemy actually runs for you:
#   CREATE TABLE enrollment (id INTEGER PRIMARY KEY,
#                            student VARCHAR(100) NOT NULL,
#                            course  VARCHAR(100) NOT NULL);
#   INSERT INTO enrollment (student, course) VALUES (?, ?);

pip install flask flask-sqlalchemy
python app.py

Swap any layer, the others don't care

Want to change…ReplaceWithWhat else changes?
FrontendPlain HTML + JSReact / Vue / StreamlitNothing. The API stays the same.
BackendFlaskFastAPI / Express / Spring BootNothing, as long as the URLs and JSON stay the same.
PersistenceSQLitePostgreSQL / MySQLOne line: the connection string.

This is the main benefit of layering: separation of concerns. Each layer can be changed, scaled or handled by a different team on its own.
