02 · The ReAct loop

Think → Act → Observe, until the LLM stops asking for tools

create_agent builds a LangGraph with two nodes: the model and the tools. After each model reply it checks for tool_calls. If there are any, it runs them and goes back to the model. If not, the loop ends.

🧠 THINK
LLM reads the rules + all messages and replies with an AIMessage holding tool_calls.
msg.type == "ai" and msg.tool_calls
🛠 ACT
LangGraph runs the matching Python @tool function with the arguments the LLM chose, e.g. {'city': 'Hyderabad'}.
🔎 OBSERVE
The tool's return string becomes a ToolMessage added to state, and the loop goes back to THINK.
msg.type == "tool"
🤖 ANSWER
An AIMessage with no tool calls ends the loop. main.py prints it as the prediction.
msg.type == "ai"

04 · Design choices in the code

Why it's built this way

A few small choices make the agent work reliably with a small local model.

🧮 Tools fetch their own data

temperature_trend takes only a city, not a list of numbers. Small models like llama3.2 3B often garble long number lists when copying them into a tool call.

🎯 temperature = 0

Deterministic output: the same data gives the same decisions and answer every run, which suits a step-by-step recipe.

📜 A strict recipe

The system prompt lists the exact order (tool 1, tool 2, answer) and forbids invented numbers, so the model only reasons over tool output.

🧱 Helpers vs tools

find_city and fetch_daily are plain functions the LLM can't see. Only @tool functions are exposed, keeping its choices small.

📡 Built-in fact check

official_forecast runs outside the agent and prints Open-Meteo's own forecast for tomorrow, so you can judge the prediction.

🔒 Local brain, free data

The LLM runs on your PC through Ollama, so no prompts leave the machine. Only the city name and coordinates go to Open-Meteo, which needs no key.
