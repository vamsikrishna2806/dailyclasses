Build Your First GenAI App — and deploy it free

A complete, step-by-step guide to Book GenAI Studio: upload any book, then summarize it, chat with it, and turn it into quizzes, notes and posts. Python (FastAPI) backend, plain HTML/JS frontend, OpenAI API, deployed on Vercel's free plan.

The finished code is in day9/book_genai_studio/. Each step below names the file it builds. Read the step, open the file, and run it.

1. What we build

📝 Summarizer
Whole book, one chapter, or pasted text. 6 styles, 3 lengths. Handles books far bigger than the model's context window.
💬 Q&A bot
Multi-turn chat about the book. Streams the answer, cites the passages ([S1] → chapter, page), says “not in the book” instead of guessing.
✨ Content generator
Quiz, flashcards, study notes, blog post, social thread, newsletter, lesson plan, timeline…
📊 Usage + 🧪 Prompt Lab
Tokens and cost of every call, ratings per prompt version, blind A/B tests.

Why a backend at all? The Day 5 app called OpenAI straight from the browser. That works for practice, but a backend lets us: hide the server's key, read PDFs and EPUBs, search a book, count tokens on the server, log usage in one place, and enforce a spending limit.

4. Config and token counting config.py · tokens.py

Put every setting in one file, read from environment variables, so the same code runs on your laptop and on Vercel.

ON_VERCEL = bool(os.getenv("VERCEL"))          # Vercel sets this automatically
DATA_DIR = Path("/tmp/book_studio" if ON_VERCEL else BASE_DIR / "data")   # only /tmp is writable there
MAX_UPLOAD_MB = float(os.getenv("MAX_UPLOAD_MB", "4" if ON_VERCEL else "25"))
DAILY_BUDGET_USD = float(os.getenv("DAILY_BUDGET_USD", "0"))
PRICES = {"gpt-4o-mini": (0.15, 0.60), ...}   # USD per 1M tokens (input, output) – keep updated

Tokens are the pieces of text a model reads and bills for (~¾ of a word in English). Count them before calling, to show the cost and to decide whether text fits in one call:

import tiktoken
enc = tiktoken.get_encoding("o200k_base")      # the tokenizer used by gpt-4o models
def count_tokens(text): return len(enc.encode(text, disallowed_special=()))
def estimate_cost(model, tokens_in, tokens_out):
    p_in, p_out = PRICES[model]
    return (tokens_in * p_in + tokens_out * p_out) / 1_000_000
If tiktoken can't load (no internet on first run), the code falls back to len(text) // 4. Always have a fallback.

5. One OpenAI wrapper with real error handling llm.py

Never call OpenAI from many places. One function = one place for retries, timeouts, logging and error messages.

client = OpenAI(api_key=key, timeout=60, max_retries=2)   # SDK retries 429/5xx with backoff

def chat(messages, *, key, feature, model, max_tokens=1200):
    check_budget()                                       # stop if today's $ limit is reached
    t0 = time.time()
    try:
        r = client.chat.completions.create(model=model, messages=messages,
                                           max_completion_tokens=max_tokens)
    except openai.OpenAIError as e:
        err = map_error(e)                               # → friendly LLMError
        db.log_usage(feature, model, 0, 0, 0, ms(t0), ok=False, error=err.code)
        raise err
    u = r.usage
    db.log_usage(feature, model, u.prompt_tokens, u.completion_tokens,
                 estimate_cost(model, u.prompt_tokens, u.completion_tokens), ms(t0))
    return r.choices[0].message.content

Turn each SDK error into something a user can act on:

OpenAI errorHTTPWhat the user sees
AuthenticationError401“OpenAI rejected the API key.” → open Settings
RateLimitError (insufficient_quota)402“Out of credit” → add billing, or use Demo mode
RateLimitError429“Too many requests” → wait and retry
BadRequestError (context_length)400“Text too long” → pick one chapter
NotFoundError404“Model doesn't exist for this key” → choose another
APITimeoutError / APIConnectionError504 / 503“Took too long” / “Couldn't reach OpenAI”

In main.py one handler turns every LLMError into JSON: {"error": {"code", "message", "hint"}}. The frontend shows message + hint in a toast. Also check finish_reason == "length" — the answer was cut off — and tell the user.

Streaming (chat) uses the same wrapper with stream=True, stream_options={"include_usage": True} so we still get token counts at the end.

6. Reading any book books.py

Pipeline: file bytes → pages → clean text → chapters → chunks.

FormatHow
PDFpypdf.PdfReader(...).pages[i].extract_text() — keeps page numbers for citations. Scanned PDFs have no text → clear error: “run OCR first”.
EPUBIt's a ZIP: read META-INF/container.xml → the .opf file → chapter order (“spine”) → strip HTML tags.
DOCXpython-docx; “Heading 1” paragraphs become chapter titles.
TXT / MD / HTMLDecode (try UTF-8, then Windows-1252), strip tags for HTML.

Chapters: a regular expression finds lines like Chapter 3, PART TWO, # Heading, Prologue. Tiny sections (a table of contents) merge into the next one. No headings? Split into equal “Parts” of ~3,000 words.

Chunks: cut each chapter into ~450-token passages on paragraph boundaries, carrying the last short paragraph into the next chunk (overlap) so ideas aren't cut in half.

for p in paragraphs:
    if buf and buf_tokens + count_tokens(p) > 450:
        flush()                          # save chunk with its chapter + page
        buf = [buf[-1]] if short(buf[-1]) else []   # overlap
    buf.append(p)

Validate early with clear messages: unsupported type (415), empty file, too large (413), no text found (422), book too long.

7. Search: keywords + meaning retrieval.py

BM25 keyword search
Free, instant, great for names (“Elias”, “A.O.”). Scores a passage higher when it contains rare words from the question. Always on.
Embedding search
With a key, each chunk becomes a vector (text-embedding-3-small, ~$0.02 per 1M tokens — a whole novel costs under a cent). Finds passages with the same meaning.

Combine both with Reciprocal Rank Fusion: each list gives a passage 1 / (60 + rank) points; add them up. Simple and robust.

fused = Counter()
for ranked in [bm25_ranking, embedding_ranking]:
    for rank, i in enumerate(ranked[:50]):
        fused[i] += 1 / (60 + rank)
top6 = [chunks[i] for i, _ in fused.most_common(6)]

8. Versioned prompts prompts.py

Keep every prompt in one file with a version. Each output stores which version made it, so ratings tell you which prompt is better.

QA = {
  "v1": {"label": "Baseline", "system": "Answer the user's question using the context below.\n{context}"},
  "v2": {"label": "Cited & honest", "system":
     "You are a reading assistant for “{title}”. Answer ONLY from the numbered sources.\n"
     "1. Cite every claim like [S2].\n"
     "2. If the sources don't contain the answer, say “I couldn't find that in the book.” Never guess.\n"
     "3. Under 200 words unless asked. Use Markdown.\n\nSOURCES:\n{context}"},
}
def pick_version(feature, requested):
    return requested if requested in FEATURES[feature] else random.choice(list(FEATURES[feature]))  # A/B

Good prompt habits used here: give a role, clear rules, an exact format and length, delimit the source text with """, tell the model what to do when it doesn't know, and ask it to self-check against the source.

9. The three features services.py

9a. Summarizer — map-reduce for long text

A whole book doesn't fit (or is expensive) in one prompt. So:

  1. Map: for each chapter, make dense notes (120–250 words). Long chapters are split into 6k-token pieces first. Pieces run in parallel (4 threads).
  2. Reduce: send all chapter notes in one call and ask for the final summary in the chosen style and length.

The browser runs the map step (one request per chapter, 3 at a time) and shows a progress bar. That keeps each request short — essential on Vercel (see §13). Chapter notes are cached so the second summary is almost free.

9b. Q&A bot — multi-turn, streaming, cited

  1. Trim history to the newest ~3,000 tokens (cost control).
  2. If it's a follow-up, ask the model to rewrite it as a standalone question (“what did he promise?” → “What did Elias promise Adaeze?”). Search with that.
  3. Retrieve the top 6 passages, tag them [S1]…[S6] with chapter and page.
  4. Stream the answer as Server-Sent Events: meta (sources) → many delta (text) → done (usage) or error.
def chat_events(...):
    yield f"event: meta\ndata: {json.dumps({'sources': sources})}\n\n"
    for piece in llm.chat_stream(msgs, ...):
        yield f"event: delta\ndata: {json.dumps({'t': piece})}\n\n"
    yield f"event: done\ndata: {json.dumps({'usage': meter.to_dict()})}\n\n"

@app.post("/api/chat")
def chat(body: ChatIn):
    return StreamingResponse(chat_events(...), media_type="text/event-stream")

Errors during the stream are sent as an error event, so the browser never hangs.

9c. Content generator

Choose the material (chapter text, passages found for a topic, evenly spaced passages from the whole book, or pasted text), then fill a template with the content type, tone, audience and extra instructions. 11 content types are defined in CONTENT_TYPES — add your own with one line.

9d. Demo mode (no key)

Each feature has an offline fallback: extractive summary (picks the most important sentences), keyword-search answers built from matching sentences, fill-in-the-blank quizzes. It lets students try everything for free — and is a useful baseline: the AI version must clearly beat it.

12. Deploy free on Vercel — step by step

Vercel's Hobby plan is free for personal, non-commercial projects and runs Python (FastAPI) as serverless functions. Two files make it work:

# api/index.py – Vercel runs this file for every request
import os, sys
sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from app.main import app
// vercel.json – send every URL to that function, bundle the static files
{
  "rewrites": [{ "source": "/(.*)", "destination": "/api/index" }],
  "functions": {
    "api/index.py": { "maxDuration": 60, "includeFiles": "{app,static,samples}/**" }
  }
}

Vercel installs requirements.txt automatically. .vercelignore keeps data/, tests/ and .env out of the upload.

14. Protect your API key and wallet

If OPENAI_API_KEY is set on a public URL, anyone who finds the link uses your credit.
  • Safest for a public demo: don't set a server key. Visitors paste their own key in ⚙️ Settings. It stays in their browser and goes only to your server in the X-OpenAI-Key header, which uses it for that request and never stores it.
  • If you do set a server key: set DAILY_BUDGET_USD, set a monthly limit in your OpenAI dashboard (Settings → Limits), use a separate key just for this project, and limit ALLOWED_MODELS to cheap ones.
  • Never put a key in frontend code or in git. Rotate it if it ever leaks.
  • Vercel Hobby also offers Deployment Protection (password / Vercel login) for preview URLs.

17. Evaluate and iterate (user testing)

  1. Test with 5 real users using the task script in EVALUATION.md: upload a book, summarize, ask 3 questions including a follow-up, check a source, make a quiz, rate everything. Watch silently; note where they get stuck.
  2. Collect ratings in the app: ★1–5 + comment on every output, 👍/👎 on chat answers. Each rating stores the prompt version.
  3. Measure: average rating per version, % happy, grounded-answer rate (do [S#] passages really support the claim?), “not in the book” honesty, cost and speed from the Usage tab.
  4. Fix the top complaint by writing prompt v3 in prompts.py. Change one thing at a time.
  5. Blind compare v2 vs v3 in Prompt Lab (labels hidden, order random) — 20+ votes. Keep the winner, log the change in EVALUATION.md. Repeat.
