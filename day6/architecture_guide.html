1. Purpose of the Application

Why this application exists and what problem it solves.

End-User Value

Real-World Student Utility

Students often get overwhelmed by bloated productivity apps requiring logins, subscriptions, and complex settings. The Student Task Tracker provides a distraction-free, lightning-fast workspace to:

  • Quickly jot down homework, reading chapters, or exam prep goals.
  • Maintain clarity with instant completion checkmarks and strikethroughs.
  • Keep tasks persistently stored on disk without internet accounts.
  • Work seamlessly across smartphones, tablets, and laptops.
Engineering Value

Educational & Pedagogical Purpose

For beginner and intermediate software engineers, this application serves as the gold standard for learning foundational full-stack concepts without framework "magic":

  • Understanding REST APIs: Learning how HTTP verbs (GET, POST, PATCH, DELETE) correspond to CRUD operations.
  • Database Security: Writing pure SQL queries with parameterized ? placeholders to master SQL injection defense.
  • Asynchronous UI: Using vanilla JavaScript fetch() and DOM updates without reloading the page.

2. System Architecture (3-Tier Design)

How the frontend, backend server, and database layers decouple responsibilities.

Tier 1: Presentation Tier (Client / Browser)

Frontend

Runs inside the user's browser. Responsible for layout rendering, user event capturing, responsive design, and communicating asynchronously via JSON.

Files: templates/index.html • static/style.css • static/app.js
↕ HTTP / HTTPS Network Boundary (JSON Payloads) ↕

Tier 2: Application Tier (Python Flask Server)

Backend Server

Python Flask WSGI web server listening on localhost:5000. Validates client payloads (checks length and empty strings), dispatches REST routes, and handles business rules.

Files: app.py • routes: GET/POST/PATCH/DELETE /api/tasks
↕ Python sqlite3 In-Process Connection ↕

Tier 3: Data Tier (SQLite Database)

Persistence

File-based ACID-compliant database stored directly on disk at tasks.db. Auto-creates the schema and executes parameterized queries.

Files: database.py • tasks.db (Table: tasks)

File Responsibility Matrix

File Name Role & Responsibility Technology
app.py Flask server, route handler, payload validation, status code emission Python / Flask
database.py Database initialization, raw SQL parameterized queries, connection pooling Python / sqlite3
templates/index.html Accessible semantic UI markup, form controls, error banner, task list placeholder HTML5
static/style.css Responsive mobile-first layout, typography, touch target padding, transitions CSS3 (Variables)
static/app.js Event listeners, fetch() REST calls, DOM manipulation, XSS sanitization Vanilla JavaScript (ES6)
tasks.db Single-file local relational store holding task records persistently SQLite 3

3. Application Flow & Lifecycles

Click the tabs below to explore the lifecycle of each operation step by step.

Flow: Adding a New Task (POST /api/tasks)

Step 1: Student Enters Task & Submits

Student types "Read Chapter 3 of Biology" into #taskTitleInput and clicks Add Task (or hits Enter).

Step 2: Client-Side Pre-Validation (app.js)

JavaScript intercepts form.submit, calls e.preventDefault(), strips whitespace, and checks if input is empty or > 200 characters. If invalid, displays #errorBanner immediately without hitting the network.

Step 3: Asynchronous Fetch Request

JavaScript sends an HTTP POST request: 

fetch('/api/tasks', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ title: 'Read Chapter 3 of Biology' })
})

Step 4: Server Validation & Parameterized Insert (app.py & database.py)

Flask receives JSON body. Validates title. Calls database.add_task(title) which runs: 

INSERT INTO tasks (title, done, created_at) VALUES (?, 0, ?)
Database assigns a new auto-increment ID and commits.

Step 5: Server Responds & DOM Updates

Flask responds with HTTP 201 Created and new task JSON. app.js clears the input field, resets the character counter, and calls loadTasks() to refresh the list with newest tasks first.

Flow: Fetching & Rendering Tasks (GET /api/tasks)

Step 1: Page Load Trigger

When the DOM content loads (DOMContentLoaded event), loadTasks() is invoked.

Step 2: GET Request to Flask API

Client sends fetch('/api/tasks') to the backend.

Step 3: SQL Query Execution

database.get_all_tasks() runs: 

SELECT id, title, done, created_at FROM tasks ORDER BY id DESC
Sorting by id DESC ensures newly added tasks always appear at the top.

Step 4: Dynamic DOM Rendering

JavaScript parses the returned JSON array. For each task, it builds an <li> element, binds the checkbox event and delete button event, and updates the task stats counter (e.g., "1 of 3 done").

Flow: Toggling Task Status (PATCH /api/tasks/<id>)

Step 1: Checkbox Change Event

Student clicks the checkbox next to a task.

Step 2: HTTP PATCH Dispatch

JavaScript calls: 

fetch(`/api/tasks/${taskId}`, { method: 'PATCH' })

Step 3: Atomic Inversion in Database

database.toggle_task(id) flips done from 0 to 1 (or 1 to 0): 

UPDATE tasks SET done = ? WHERE id = ?

Step 4: Visual Strikethrough & Counter Update

Server responds with 200 OK. UI applies the CSS class .is-done which adds text-decoration: line-through and updates completed counts.

Flow: Deleting a Task (DELETE /api/tasks/<id>)

Step 1: Delete Button Click

Student clicks the red "Delete" button on a task item.

Step 2: HTTP DELETE Request

JavaScript calls: 

fetch(`/api/tasks/${taskId}`, { method: 'DELETE' })

Step 3: Database Removal

database.delete_task(id) executes: 

DELETE FROM tasks WHERE id = ?

Step 4: DOM Removal & Empty State Check

The row is removed from the DOM. If zero tasks remain, the empty state message ("No tasks yet! Add your first study task above.") is revealed.

Flow: Automatic Startup & Database Provisioning

Step 1: Terminal Launches Server

Running python app.py starts the Python interpreter.

Step 2: database.init_db() Invocation

Before any web requests are served, app.py calls database.init_db().

Step 3: SQLite File & Table Creation

If tasks.db does not exist, SQLite creates the file and executes: 

CREATE TABLE IF NOT EXISTS tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    done INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL
);

Step 4: Server Enters Event Loop

Flask starts listening on http://127.0.0.1:5000 ready to accept student requests.

4. Step-by-Step Build Roadmap

The exact sequential engineering workflow to build this project from scratch.

1

Initialize Environment & Dependencies

Create an isolated virtual environment and install Flask.

# Create virtualenv
python -m venv .venv

# Activate on Windows:
.venv\Scripts\activate

# Install Flask
pip install flask
pip freeze > requirements.txt
2

Create Database Layer (database.py)

Write standard SQLite helper functions: get_db_connection(), init_db(), get_all_tasks(), add_task(), toggle_task(), and delete_task() using parameterized queries ?.

3

Build Web Server & REST Endpoints (app.py)

Set up Flask instance, register route / to serve HTML, and implement RESTful endpoints /api/tasks with status codes (200, 201, 400, 404).

4

Structure Frontend HTML (templates/index.html)

Write clean semantic markup with accessible labels, form inputs, character counter, error banner, and task list placeholders.

5

Design Mobile-First CSS (static/style.css)

Add CSS custom properties, touch-friendly 44px tap targets, card container styling, completed task strikethrough states, and responsive media queries.

6

Implement Frontend Async Logic (static/app.js)

Wire form submissions to fetch('/api/tasks', { method: 'POST' }), render tasks with textContent to prevent XSS, handle checkbox clicks, and process delete events.

7

Test & Verify

Run python app.py, open http://localhost:5000 in your browser, test validation, add 3 sample tasks, and inspect the SQLite database file directly with sqlite3 tasks.db.

5. Security & Engineering Best Practices

Essential security principles implemented in this application.

SQL Protection

Parameterized Queries

Never concatenate raw strings into SQL (e.g., f"INSERT... '{title}'"). Using ? placeholders tells SQLite to treat inputs as literal data values, making SQL injection impossible.

XSS Defense

Safe DOM Rendering

In app.js, tasks are rendered using element.textContent = task.title rather than innerHTML. This ensures malicious <script> tags are treated as plain text.

Validation

Dual-Layer Validation

Validation occurs on the client for immediate UI feedback, and is strictly enforced on the server in app.py (non-empty, ≤ 200 chars) in case a request bypasses the browser.
