Day 2: Comparing LLMs

Claude, GPT, Gemini and open-source models: who to use, when, and how to test them yourself

1 🗺️ The Model Landscape

Today's language models fall into two families. Enterprise (closed) models are hosted by a company and reached through an API or a chat app. Open-weight models publish their weights, so you can run them on your own machine or cloud, or pick a hosting provider.

Closed · Anthropic

Claude 3 family

Strengths: careful reasoning, long documents, strong safety behaviour.

Sizes: Haiku (fast), Sonnet (balanced), Opus (most capable).

Closed · OpenAI

GPT-4 family

Strengths: versatility across writing, coding, reasoning and tool use.

Ecosystem: very wide third-party tooling and examples.

Closed · Google

Gemini

Strengths: multimodal input (text, images, audio, video) and very long context windows.

Ecosystem: tight integration with Google Cloud and Workspace.

Open weights · Meta

Llama 2 / Llama 3

Strengths: free weights, run privately, fine-tune freely.

Sizes: 7B, 13B, 70B (Llama 2); 8B and 70B (Llama 3).

Open weights · Mistral AI

Mistral & Mixtral

Strengths: fast inference for its size; Mixtral uses a mixture-of-experts design.

Sizes: Mistral 7B; Mixtral 8x7B.

Key idea: "Open" and "closed" describe how you get the model, not how good it is. The right choice depends on the task, the budget, the privacy needs and how much control you need.

2 📏 Model Size: 7B to 70B+ Parameters

A parameter is one learned number inside the model. More parameters usually mean more knowledge and better reasoning, but also more memory, slower responses and higher cost.

Rough size comparison (open models)

Bars are relative to a 70B model. Closed-model sizes are not published, so they are not shown.

Bigger isn't always better. A well-trained 7B or 8B model can beat an older 70B model on narrow tasks, and it runs on a single consumer GPU or a laptop. Start small and move up only when quality requires it.

3 🪟 Context Windows: 4K to 1M+ Tokens

The context window is how much text (in tokens, roughly ¾ of a word) the model can read and respond to in one go: your prompt, the conversation so far, and any documents you paste in.

Context sizes change with each release. Check each provider's documentation for the current value.

4 ⚡ Latency & Cost

Latency is how long you wait. Two numbers matter: time to first token (how soon text starts appearing) and tokens per second (how fast it streams).

Cost is usually charged per million input tokens and per million output tokens. Output tokens are typically more expensive. Self-hosted open models cost you hardware and electricity instead of per-token fees.

OptionLatencyCost patternBest when
Small hosted model (e.g. Haiku-class, Mistral 7B)Very lowLow per tokenHigh-volume, simple tasks
Large hosted model (e.g. Opus-class, GPT-4-class)HigherHigh per tokenHard reasoning, important outputs
Self-hosted 7B–8B on a GPULow on your own hardwareFixed hardware costPrivacy, steady heavy use
Self-hosted 70BNeeds large GPUsExpensive hardwareStrong open model, in-house
Quick cost estimate: cost = (input tokens × input price + output tokens × output price) ÷ 1,000,000, multiplied by the number of requests. Always check the provider's current price sheet, because prices change often.

6 🧪 Hands-On: Test Models via APIs

Reading about models is not enough. The fastest way to compare is to send the same prompts to several models and score the answers yourself. The script below does that for three providers. Each one needs its own API key (set as an environment variable), and the local Ollama option runs Llama and Mistral for free on your machine.

benchmark_models.py 
import os, time, json, csv
import requests
from anthropic import Anthropic
from openai import OpenAI

PROMPTS = [
    "Summarize this in one sentence: Photosynthesis converts light, water and CO2 into glucose and oxygen.",
    "Write a Python function that returns the n-th Fibonacci number.",
    "A bat and a ball cost $1.10 in total. The bat costs $1.00 more than the ball. How much is the ball?",
]

def run_claude(prompt):
    client = Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
    msg = client.messages.create(
        model="claude-sonnet-5-5",          # use the model ID from your provider's docs
        max_tokens=512,
        messages=[{"role": "user", "content": prompt}],
    )
    return msg.content[0].text, msg.usage.input_tokens, msg.usage.output_tokens

def run_openai(prompt):
    client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])
    r = client.chat.completions.create(
        model="gpt-4o",                     # any chat model you have access to
        messages=[{"role": "user", "content": prompt}],
    )
    return r.choices[0].message.content, r.usage.prompt_tokens, r.usage.completion_tokens

def run_ollama(prompt, model="llama3"):   # local model, e.g. "mistral" or "llama3"
    r = requests.post("http://localhost:11434/api/generate",
                      json={"model": model, "prompt": prompt, "stream": False})
    d = r.json()
    return d["response"], d.get("prompt_eval_count", 0), d.get("eval_count", 0)

MODELS = {
    "claude": run_claude,
    "gpt-4o": run_openai,
    "llama3 (local)": run_ollama,
}

rows = []
for name, fn in MODELS.items():
    for i, prompt in enumerate(PROMPTS, 1):
        start = time.perf_counter()
        try:
            answer, tin, tout = fn(prompt)
        except Exception as e:
            answer, tin, tout = f"ERROR: {e}", 0, 0
        latency = time.perf_counter() - start
        rows.append({
            "model": name, "prompt_no": i, "latency_s": round(latency, 2),
            "input_tokens": tin, "output_tokens": tout,
            "tokens_per_s": round(tout / latency, 1) if latency else 0,
            "answer": answer.strip(),
        })
        print(f"{name:16} prompt {i}  {latency:5.2f}s  {tout} out-tokens")

with open("benchmark_results.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=rows[0].keys())
    writer.writeheader()
    writer.writerows(rows)

print("Saved benchmark_results.csv: open it, read the answers and score each one.")

How to score the answers

Use a simple rubric so every model is judged the same way. Score each answer 1–5 on these criteria, then average them:

  • Correctness: is the fact or code right? (the bat-and-ball question has a trap answer of $0.10)
  • Instruction following: one sentence means one sentence
  • Speed: the latency_s column
  • Cost: token counts × the provider's price

7 🎓 What You Learned Today

  • Enterprise models (Claude, GPT-4, Gemini) are strong, easy to start with, and hosted for you.
  • Open models (Llama, Mistral) give you privacy, control and fine-tuning, at the cost of running them yourself.
  • Size, context window, latency and cost are the four numbers to compare before you choose.
  • Match the model to the job: chatbots favour speed and cost; coding and analysis favour reasoning and context; sensitive data favours self-hosting.
  • Always benchmark on your own prompts. A simple script and a scoring rubric beat any leaderboard for your use case.

Model names, context sizes and prices change frequently. Verify against each provider's current documentation before making a decision.
