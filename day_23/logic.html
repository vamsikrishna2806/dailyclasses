Day 23 — Ollama talks to a live MCP server

A local Ollama model (llama3.2) connects to a free, public MCP server on the internet (DeepWiki) and uses its tools to answer questions about any GitHub repo.

day_23/ollama_mcp_client.py

What it does: you type a question about a GitHub repo. Ollama decides to call a DeepWiki tool, the program runs that tool on the remote server, and Ollama writes the final answer from the result.

Setup with a venv (Windows)
cd D:\getwork\day_23 python -m venv .venv .venv\Scripts\activate pip install -r requirements.txt ollama pull llama3.2

macOS/Linux: use source .venv/bin/activate instead. When the venv is active, your prompt starts with (.venv).

Run
python ollama_mcp_client.py
PowerShell error "running scripts is disabled"? Run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned once, or skip activating and run the venv's Python directly: .venv\Scripts\python.exe ollama_mcp_client.py. Type deactivate to leave the venv. The .venv folder is in .gitignore, so it is not committed.
Why mcp<2 in requirements.txt? In mcp version 2, streamablehttp_client was renamed, so this program fails with ImportError. Installing from requirements.txt gets version 1.x, which works.
What you need
  • Python 3.10 or newer
  • Ollama installed and running (ollama.com), with the llama3.2 model pulled
  • Internet connection (the MCP server is online)
  • No API key and no account: DeepWiki is free
Logic step by step
  1. Connect. streamablehttp_client("https://mcp.deepwiki.com/mcp") opens an HTTP connection. ClientSession wraps it and initialize() does the MCP handshake.
  2. Get tools. session.list_tools() asks the server what it can do. DeepWiki returns 3 tools: read_wiki_structure, read_wiki_contents, ask_wiki_question.
  3. Convert tools. Each MCP tool (name, description, inputSchema) is put into the format Ollama wants: {"type":"function","function":{...}}.
  4. Ask Ollama. The question and the tool list go to ollama.chat(...). Ollama does not run tools itself — it only replies with tool_calls saying which tool and which arguments.
  5. Run the tool. For each tool call, session.call_tool(name, args) sends it to DeepWiki over the internet. The text result is added to messages with role: "tool".
  6. Final answer. ollama.chat is called again with the whole conversation. Now Ollama has real data and writes the answer.
The messages list grows like this
#rolecontent
1userWhat is the repo modelcontextprotocol/python-sdk about?
2assistanttool_calls: ask_wiki_question(repoName=..., question=...)
3toolText answer from DeepWiki (cut to 6000 chars)
4assistantFinal answer written by Ollama

Every line explained

What happens inside, in the order the program runs.

Comments
# Ollama + free live MCP server (DeepWiki) - very simple version
# pip install -r requirements.txt      |      ollama pull llama3.2
Notes for humans. Python skips them. The second line says what to install first: the packages in requirements.txt and the llama3.2 model.
Imports
import asyncio
Lets Python wait for slow things (network replies) without freezing. The MCP library is built on it.
import ollama
The Ollama library. ollama.chat(...) sends an HTTP request to the Ollama app on your computer (http://localhost:11434). The model runs there, not inside Python.
from mcp import ClientSession
The object that speaks MCP. It turns Python calls like list_tools() into MCP messages and turns replies back into Python objects.
from mcp.client.streamable_http import streamablehttp_client
The transport, the "phone line" to a remote MCP server over HTTP. It only sends and receives raw messages. ClientSession understands what they mean.
Main function
async def main():
async def makes a function that can use await. We need it because talking to the server takes time.
Connect to the MCP server
async with streamablehttp_client("https://mcp.deepwiki.com/mcp") as (read, write, _):
  • Opens an HTTP connection to DeepWiki's free MCP server.
  • Gives back 3 things: read (receive messages), write (send messages), and a session-id helper we don't need, so we call it _.
  • async with closes the connection automatically when the block ends, even after an error.
async with ClientSession(read, write) as session:
Wraps the raw streams in an MCP session. From now on we only use session.
await session.initialize()
The MCP handshake. The client says hello with its protocol version, and the server answers with its version and what it offers ("I have tools"). Every MCP connection starts with this.
Step 1: Get the tools
tools = (await session.list_tools()).tools
  • Sends a tools/list request to the server.
  • DeepWiki replies with 3 tools: read_wiki_structure, read_wiki_contents, ask_wiki_question.
  • Each tool has a name, a description and an inputSchema (which arguments it needs).
  • .tools takes the list out of the reply.
ollama_tools = [{"type": "function", "function": {"name": t.name, "description": t.description, "parameters": t.inputSchema}} for t in tools]
MCP and Ollama describe tools in slightly different formats, so this line translates them. For each tool t it builds a dictionary in Ollama's format, and MCP's inputSchema becomes Ollama's parameters. Now Ollama can read the "tool menu".
Step 2: Ask Ollama
question = input("Ask about a GitHub repo: ")
Waits for the student to type a question, for example "What is modelcontextprotocol/python-sdk about?"
messages = [{"role": "user", "content": question}]
Starts the conversation history. LLMs have no memory, so we send the whole conversation every time. role: "user" means "the human said this".
reply = ollama.chat(model="llama3.2", messages=messages, tools=ollama_tools)
  • Sends the question and the tool menu to Ollama.
  • The model reads the tool descriptions and decides a tool would help, so it picks ask_wiki_question.
  • It does not run the tool. It only replies with a request: ask_wiki_question(repoName="modelcontextprotocol/python-sdk", question="...")
messages.append(reply.message)
Saves Ollama's reply (with its tool request) in the history, so next time Ollama remembers it asked for this tool.
Step 3: Run the tool
for call in reply.message.tool_calls or []:
Loops over every tool Ollama asked for. or [] is a safety trick: if Ollama asked for no tool, tool_calls is None, so the loop runs zero times instead of crashing.
print("Calling tool:", call.function.name)
Shows which tool was chosen, for example Calling tool: ask_wiki_question.
result = await session.call_tool(call.function.name, call.function.arguments)
The real work. Python sends a tools/call request over the internet with the tool name and the arguments Ollama chose. DeepWiki looks up the repo and sends back text.
messages.append({"role": "tool", "content": result.content[0].text[:6000]})
  • result.content is a list of pieces, and [0].text takes the first piece's text.
  • [:6000] keeps only the first 6000 characters, so a small model isn't overloaded.
  • role: "tool" tells Ollama "this is the tool's result".
Step 4: Final answer
final = ollama.chat(model="llama3.2", messages=messages)
Calls Ollama again with the full history: the question, the tool request and the facts from DeepWiki. Now the model has real facts and writes a proper answer. We don't pass tools this time because we just want the answer.
print("\nAnswer:", final.message.content)
Prints the answer. \n adds a blank line first.
Run it
asyncio.run(main())
main() is async, so it can't be called like a normal function. asyncio.run starts the event loop, runs main() to the end, then closes everything.
The whole thing in one picture
You ──question──► Python ──question + tools──► Ollama 🧠
                                                  │
                     "please run ask_wiki_question"
                                                  ▼
DeepWiki 🧰 ◄──tools/call── Python ◄──────────────┘
     │
     └──result──► Python ──history + result──► Ollama 🧠 ──answer──► You
Key idea: the LLM chooses the tool, your Python code runs it. MCP is just the standard way to list and call tools on a server — local or remote.
Note: use a model that supports tool calling (llama3.2, qwen2.5). [:6000] keeps the tool result small so a small model is not overloaded. If the model answers without calling a tool, the loop simply runs zero times.
