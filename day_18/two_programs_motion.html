Two small programs, two problems

LangChain and LangGraph, side by side

Each program starts with a problem. Read the problem first, then watch the program solve it. The first is a straight line. The second needs a loop.

Program 1 · LangChain

A straight job: summarize a review

The problem. You have a long customer review. You want one short line that says what the customer thinks. Every review follows the same steps, in the same order. No decisions, no retries. 
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_openai import ChatOpenAI          # any chat model works

prompt = ChatPromptTemplate.from_template("Summarize in one line: {review}")
model = ChatOpenAI(model="gpt-4o-mini")
parser = StrOutputParser()

chain = prompt | model | parser                  # the straight line
print(chain.invoke({"review": "The phone is fast, but the battery dies by noon."}))
Holding nowThe phone is fast, but the battery dies by noon.
Press Run. Each box does one job, then passes the value on.
What goes wrong without a chain?

You would write the same three calls by hand, in the right order, for every review. A chain names the steps once and reuses them. It only fails when a step needs to go back, which is Program 2's problem.

Program 2 · LangGraph

A job that must repeat: write until good

The problem. A helper writes a draft answer. A checker decides if it is good enough. If not, the helper must write again. Stop after a good draft, or after three tries. A straight line cannot go back, so this needs a loop with a decision. 
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    question: str
    draft: str
    tries: int

def write(state: State) -> dict:
    # a real app would call an LLM here
    n = state["tries"] + 1
    return {"draft": f"Answer v{n}", "tries": n}

def check(state: State) -> str:
    # the decision: pick the next arrow
    return "done" if state["tries"] >= 3 else "retry"

graph = StateGraph(State)
graph.add_node("write", write)
graph.add_edge(START, "write")
graph.add_conditional_edges("write", check, {"retry": "write", "done": END})
app = graph.compile()

print(app.invoke({"question": "What is LangGraph?", "draft": "", "tries": 0}))
State (the notebook){ question: "What is LangGraph?", draft: "", tries: 0 }
Press Run. Watch the loop: Write, Check, Write again.
What goes wrong without a loop?

A plain chain runs once and stops, so the draft is never checked. You could copy the steps three times, but then you would have to guess how many tries to make. The graph holds the count in state and decides at each check.

Which one, and why

Look at the problem first. Ask one question: does the work ever go back?

No: a straight job

Use a LangChain chain. Program 1.

Yes: loops or decisions

Use LangGraph. Program 2.
